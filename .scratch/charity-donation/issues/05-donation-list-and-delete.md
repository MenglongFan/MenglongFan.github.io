# 05: 捐赠记录逐笔列表与删除

**What to build:** 房主能打开「捐赠记录」看到每一笔捐赠——捐赠人、金额、时间、操作后余额、备注——并且能删掉录错的那一笔，不用为了改一个数字去直连数据库。删除前要明确告知这不是一个局部操作：奖池余额会重算、该玩家的累计额与称谓也会跟着变。删除后列表、奖池余额、慈善榜、流水一起更新。

这一票真正的难点在**余额链**。奖池余额的真相不是「所有金额之和」，而是「id 最大的那一行的余额字段」。所以删掉中间一笔之后，被删记录之后的**每一行**都必须按新的前驱重算余额；只改被删那条、或者只改最后一条，都会留下一条断掉的链，此后每一屏显示的余额都是错的，而且**不会自愈**——没有任何机制能发现它。

**Blocked by:** 04

**Status:** ready-for-agent

- [ ] 逐笔列表返回捐赠人、金额、时间、操作后余额、备注；支持分页（默认 100 条、上限 200）
- [ ] 删除需要房主密码，未带密码被拒
- [ ] 拿一条罚金或支取记录的 id 去删，必须被拒绝（罚金是赛季结算的产物、支取是账务动作，都不该从这里消失）
- [ ] 删除不存在的记录返回明确的「不存在」，不是静默成功
- [ ] 删除后，被删记录之后的**每一行**余额都被重写，逐行满足「新前驱余额 + 本行金额」；只改被删那条或只改最后一条都算失败
- [ ] 删除是原子操作：不能出现「记录已删但余额没重算完」的中间状态
- [ ] 删除导致累计额掉档时，称谓跟着回退；掉到门槛以下时不再显示称谓
- [ ] 删除后列表立刻反映结果，不会留下一条已经删掉的记录（注意本项目弹窗容器会把传入的 JSX 连同捕获的变量一起冻住）
- [ ] 二次确认文案写明余额会重算、累计额与称谓会跟着变
- [ ] 删除入口不与金额挤在同一行，窄屏上不压到数字
- [ ] 删除后奖池余额、慈善榜、流水一起更新
