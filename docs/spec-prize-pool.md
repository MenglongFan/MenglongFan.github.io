# 规格文档 · 奖池系统 & 默认花名册 & 玩家头像

> 本文档是国战积分系统的增量规格，在 `spec-guozhan-scoring.md` 基础上追加奖池、默认花名册和玩家头像三个功能模块的详细设计。

## Problem Statement

当前积分系统只记录分数排名，缺乏真实的奖惩机制。线下聚会打完一个赛季后，末位玩家需要缴纳罚金作为聚会基金，但金额计算、累计追踪、支取记录全靠手动，容易出错且没有历史可查。同时花名册需要每次手动添加，缺乏默认配置，玩家也没有视觉标识。

## Solution

在现有积分系统上增加三个模块：

1. **奖池系统**：赛季结束时自动按末三名排名计算罚金（15/10/5 元），同分平摊，跨赛季累计；支持支取操作并记录完整流水；展示各玩家贡献金额。
2. **默认花名册**：系统预置 7 名玩家（樊梦龙、齐济、赵振东、李晓阳、范昊宇、肇淘胜、祝振军），开箱即用。
3. **玩家头像**：每个玩家关联一个圆形头像，排名榜和花名册中展示。

## User Stories

### 奖池查看

1. 作为访客，我想在奖池弹窗顶部看到当前总奖池金额（大数字），所以能一眼知道基金池有多少钱。
2. 作为访客，我想在奖池弹窗中部看到各玩家贡献金额列表（从高到低排序），所以知道谁对奖池贡献最多。
3. 作为访客，我想在奖池弹窗底部看到奖池流水列表（时间+类型+金额+说明+余额），所以能追溯每一笔进出。
4. 作为访客，我可以不输入密码就能查看奖池、贡献榜和流水，因为这些是公开信息。

### 罚金计算与入账

5. 作为房主，我点击"结束赛季"时，系统自动计算末三名罚金并写入奖池，不需要手动输入金额。
6. 作为房主，赛季结束时末三名无同分的情况下，最后一名缴 15 元、倒数第二名缴 10 元、倒数第三名缴 5 元。
7. 作为房主，当末三名三者同分时，三人平摊 30 元，每人缴 10 元。
8. 作为房主，当最后一名与倒数第二名同分时，两人平摊 25 元（每人 12.5 元），倒数第三名缴 5 元。
9. 作为房主，当倒数第二名与倒数第三名同分时，两人平摊 15 元（每人 7.5 元），最后一名缴 15 元。
10. 作为房主，赛季结束后不可再增删对局或修改成绩，奖金数据被锁定。
11. 作为玩家，我在赛季结束弹窗中能看到每人应缴的罚金金额，所以清楚知道谁该交多少钱。

### 支取与流水

12. 作为房主，我可以从奖池中支取资金，需要输入房主密码鉴权。
13. 作为房主，支取时需要填写支取金额和用途说明，所以流水里能记录这笔钱花在哪。
14. 作为房主，每一笔支取都会生成一条流水记录，包含时间、金额（负数）、用途、操作后余额。
15. 作为房主，每一次赛季结束的罚金入账也会生成流水记录，包含时间、金额（正数）、所属赛季、操作后余额。
16. 作为访客，流水按时间倒序排列，最新的记录在最上面。

### 默认花名册

17. 作为房主，首次部署系统后，花名册里已有 7 名默认玩家：樊梦龙、齐济、赵振东、李晓阳、范昊宇、肇淘胜、祝振军。
18. 作为房主，我仍然可以增删花名册中的玩家，默认玩家不影响后续管理。
19. 作为房主，录入成绩选人步骤默认勾选所有花名册玩家（上限 10 人）。

### 玩家头像

20. 作为访客，排名榜中每个玩家旁边显示其圆形头像，增加视觉辨识度。
21. 作为访客，花名册弹窗中每个玩家旁边显示其圆形头像。
22. 作为房主，新增玩家时如果没有指定头像，系统分配一个默认头像（通用占位图）。
23. 作为访客，头像以圆形裁剪展示，与整体水墨风格协调。

## Implementation Decisions

### 数据库变更

新增 `prize_pool_transactions` 表记录奖池流水：

```sql
CREATE TABLE IF NOT EXISTS prize_pool_transactions (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  season_id   INTEGER REFERENCES seasons(id),  -- 赛季结束入账时关联赛季，支取时为空
  player_id   INTEGER REFERENCES players(id),  -- 罚金入账时关联缴纳玩家，支取时为空
  type        TEXT NOT NULL,                   -- 'fine' 罚金入账 | 'withdrawal' 支取出账
  amount      REAL NOT NULL,                   -- 正数=入账，负数=支取
  description TEXT,                            -- 用途说明（支取）或赛季信息（入账）
  balance     REAL NOT NULL,                   -- 操作后奖池余额
  created_at  TEXT DEFAULT (datetime('now'))
);
```

`players` 表新增 `avatar_url` 字段：

```sql
ALTER TABLE players ADD COLUMN avatar_url TEXT;
```

`seasons` 表新增 `prize_calculated` 字段标记奖金是否已计算：

```sql
ALTER TABLE seasons ADD COLUMN prize_calculated INTEGER DEFAULT 0;
```

### API 新增端点

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/api/prize-pool/summary` | 否 | 获取奖池总览：当前余额、各玩家贡献、最近流水 |
| POST | `/api/prize-pool/withdraw` | 是 | 从奖池支取资金，生成流水 |
| GET | `/api/prize-pool/transactions` | 否 | 获取奖池流水列表（分页） |
| POST | `/api/season/{id}/end` | 是 | 结束赛季，自动计算罚金并入账奖池 |

### 罚金计算算法

```
输入：赛季玩家积分榜（按总分升序，积分最低在前）
输出：每个末位玩家的应缴金额

1. 取积分榜最后三名玩家（积分最低的三个）
2. 设 s1 = 最后一名积分（最低），s2 = 倒数第二名积分，s3 = 倒数第三名积分
3. 按同分情况分支：
   a. 三者同分 (s1 == s2 == s3)：
      - 每人缴 (15 + 10 + 5) / 3 = 10 元
   b. 后两者同分 (s1 == s2 && s2 != s3)：
      - 最后两名各缴 (15 + 10) / 2 = 12.5 元
      - 倒数第三名缴 5 元
   c. 前两者同分 (s1 != s2 && s2 == s3)：
      - 最后一名缴 15 元
      - 倒数二三名各缴 (10 + 5) / 2 = 7.5 元
   d. 都不同分：
      - 最后一名 15 元、倒数第二 10 元、倒数第三 5 元
```

### 前端 UI 变更

**新增 FAB 按钮**：奖池按钮（铜钱/金元宝图标），点击打开奖池弹窗。

**奖池弹窗结构**（从上到下）：
1. 总奖池金额（大号朱砂色数字 + "元"单位）
2. "贡献榜"小标题 + 玩家贡献列表（头像+姓名+金额，从高到低）

**排名榜**：每行左侧增加圆形头像。

**花名册弹窗**：每行左侧增加圆形头像。

**新增玩家弹窗**：保留姓名输入，头像使用默认占位图。

### 赛季结束流程调整

原"结束赛季"操作仅将 `is_active` 置为 0。现调整为：

1. 校验房主密码
2. 检查赛季是否已结束，已结束则报错
3. 计算赛季末三名罚金
4. 为每名末位玩家生成一条 `fine` 类型的奖池流水（关联 season_id 和 player_id）
5. 更新赛季 `is_active = 0`、`ended_at = now()`、`prize_calculated = 1`
6. 返回赛季结果 + 罚金明细

整个操作在一个数据库事务中执行，确保原子性。

## Testing Decisions

通过 API 端到端验证以下场景：

- 正常赛季结束：7 人不同分，末三名分别缴 15/10/5 元，奖池余额 = 30 元
- 三者同分：末三名积分相同，每人缴 10 元，奖池余额 = 30 元
- 后两者同分：末两名积分相同，各缴 12.5 元，倒数第三缴 5 元，奖池余额 = 30 元
- 前两者同分：倒数二三名积分相同，各缴 7.5 元，最后一名缴 15 元，奖池余额 = 30 元
- 支取：奖池 30 元，支取 10 元，余额 = 20 元，生成支取流水
- 赛季结束后不可再录入成绩：返回 400 错误
- 默认花名册初始化：查询 players 表返回 7 条记录，各有 avatar_url

## Out of Scope

- 在线支付（罚金缴纳仍是线下现金/转账，系统只记账）
- 玩家头像自定义上传（使用静态资源，不在前端提供上传功能）
- 多奖池/分类账（只有一个总奖池）
- 支取审批流程（房主密码即可支取，无需多人审批）
- 奖池利息/投资增值
