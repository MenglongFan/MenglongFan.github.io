# 玩家不可删除

花名册只支持添加与改名，不提供删除。玩家一旦建立就长期存在，人员变动通过「新赛季不把他加进参赛名单」体现，而不是把他从花名册里抹掉。

这样做是因为「删掉玩家、保留历史」在数据上根本做不到。`match_results.player_id` 与 `prize_pool_transactions.player_id` 都外键引用 `players`，而 D1 开着外键强制、且没有任何 `ON DELETE CASCADE`。于是删除只有两种结局：要么被外键挡住（`FOREIGN KEY constraint failed`），要么在关掉外键强制的环境下删成功、留下指向不存在玩家的孤儿行——而这些行会被 `JOIN players` 的榜单直接滤掉：**人从榜上消失，他捐的钱却还留在奖池余额里**，账就此对不上。

既然「保留历史」不成立，「删除」就没有安全的语义。要删就必须连历史一起清，但历史是账本的一部分（罚金、捐赠、逐局成绩都挂在上面），不该因为人员变动而消失。所以不提供这个能力，也就不需要为它设计级联规则。

原实现与此矛盾：`DELETE /api/player/:id` 的注释写着「删除（历史记录保留）」，前端确认框也承诺「历史对局记录将保留」——这句话从来没有成立过。接口现已改为在有历史时明确拒绝，而不是抛出一个原始的外键错误。
