# ADR 0014: 是否新增微信小程序端

**状态**: 需求确认中（第一轮访谈已回填；方案未选定，按 SOP 不得进入方案输出与代码）
**日期**: 2026-11-06

## 背景

提出「把三国杀积分系统做成微信小程序或者 H5」。盘点仓库后发现 H5 形态已经完成并上线，
因此本 ADR 记录的不是「做 H5 还是做小程序」的二选一，而是**是否在既有 H5 之外新增第二个客户端**，
以及若新增，采用何种复用策略。

## 已确认的事实（现状盘点）

| 项 | 现状 |
| --- | --- |
| 前端 | React + Vite + HashRouter，源码 `react-app/`，构建产物提交进 `scoring/`，GitHub Pages 直出 `https://menglongfan.github.io/scoring/` |
| 后端 | Cloudflare Workers + D1（`worker/src/index.js`），REST API；CORS `Access-Control-Allow-Origin: *`，允许 `X-House-Key` 头（见 `worker/src/index.js:4-8`） |
| 鉴权 | 房主密码（共享口令），非账号体系。查看排名与奖池对所有人开放，写操作需口令（见 `CONTEXT.md`） |
| 领域资产 | `CONTEXT.md` 词汇表、3 份 `spec-*.md`、ADR 0001–0013 |
| 前端构建约束 | 171 个中文子集 woff2 位于 `scoring/assets/`；交互依赖 ADR 0008（Pointer Events 拖拽）与 ADR 0009（GSAP 页切换） |

结论：**H5 不是待办事项**。若「做成 H5」是唯一诉求，本 ADR 应直接以「不新增端」结案。

## 第一轮访谈回答（2026-11-06）

| 问题 | 回答 | 直接后果 |
| --- | --- | --- |
| 做端动机 | 微信内分享与常驻入口 | 只读 / 轻交互即可满足，不必全功能对齐 H5 |
| 账号主体 | **个人主体** | `web-view` 方案出局；不可开微信支付；类目限工具 / 信息展示等非经营性范围 |
| API 域名 | **只有 `workers.dev` / `github.io`** | `wx.request` 直连现有 Worker 出局，须另找通路 |
| 复用策略 | 先看成本再定 | 本 ADR 补「成本对比」节 |

## 关键死锁与破局

**死锁**：`wx.request` 只能请求后台配置的合法域名，须 HTTPS 且完成 ICP 备案，不支持 IP、`localhost`、
配置端口（微信开放文档「域名管理」/「网络」）。`guozhan-scoring.menglongfan.workers.dev` 是 Cloudflare
共享域名，无法以本主体备案；即便买自有域名，只要解析指向境外 Worker，个人 ICP 备案也难以通过接入商审核。
因此「给现有 Worker 换个备案域名」不是低成本补丁，而是**推翻 ADR 0001 后端选型**。

**破局**：微信云开发的 `wx.cloud.callFunction` 不经 `wx.request`，不触发小程序客户端的合法域名校验；
云函数在服务端发起的出站请求可访问任意外部接口，且个人主体可以开通云开发环境。
于是存在一条后端零迁移的链路：

```
小程序 (wxml/wxss) → wx.cloud.callFunction → 云函数 (转发 + 注入 X-House-Key)
                                            → 现有 Cloudflare Worker → D1
```

**仍然绕不开的**：小程序自身的工信部备案（上线前强制，个人备案审核约 7–20 工作日），
以及个人主体微信认证（约 30 元/年，以公众平台实际显示为准）。

**新增风险**：云函数在国内、Worker 在境外，跨境出站存在延迟与偶发不通；云函数外网出流量计费。
7 人低频场景量级极小，但需要在方案里明确超时与降级策略，不能假设链路稳定。

## 候选方案（第一轮后重排）

| 方案 | 做法 | 后端改动 | 状态 |
| --- | --- | --- | --- |
| A. 不新增端 | 继续 H5；群置顶链接 / 二维码 / 添加到主屏幕 | 无 | 有效，且成本最低 |
| B. 云函数代理 + 原生只读 MVP | 按页产出 wxml/wxss/js，云函数转发现有 API；MVP 只做积分榜 + 奖池两页只读，录入 / 赛季 / 花名册 / 支取仍走 H5 | 仅新增一层云函数，`worker/` 与 `schema.sql` 不动 | 有效，推荐评估 |
| C. 全量对齐 | 买域名 + ICP 备案 + 后端迁国内托管 + 全功能原生重写，拖拽排序与 GSAP 转场重做 | 推翻 ADR 0001，D1 数据迁移 | 有效，代价最高 |
| D. web-view 套现有 H5 | 小程序内嵌线上页面 | 业务域名校验文件 | **已淘汰**：个人主体不可配置业务域名、不支持 `web-view`；且「简单套壳」是常见驳回原因 |
| E. Taro/uni-app 复用 React | 跨端框架编译 | 同 B | 备选；拖拽、GSAP、171 个字体子集仍须改造，构建链变复杂 |

## 成本对比（第一轮明确要求）

| 维度 | A 不新增端 | B 云函数代理 + 只读 MVP | C 全量对齐 |
| --- | --- | --- | --- |
| 前置流程 | 无 | 小程序注册 + 个人认证 + **小程序备案 7–20 工作日** | 同上 + 域名实名 / ICP 备案 + 国内服务器 |
| 一次性成本 | 0 | 认证约 30 元；2 个原生页面 + 1 个云函数 + 提审材料 | 域名 + 服务器年费；后端迁移；全部页面重写 |
| 持续成本 | 0（现有 Pages + Worker 免费额度） | 云开发：**免费环境仅限开发阶段，发布上线后转付费 / 到期销毁**；基础套餐 **19.9 元/月**（原价 39，5 折长期有效），含 20 万次调用 / 2GB 容量 / 2GB 云函数外网出流量 | 服务器 + 域名续费 + 双端维护 |
| 工程量 | 0 | 小：只读接口已有，云函数薄转发，字体改用系统字体或按需子集 | 大：拖拽排序、GSAP 转场、弹窗模式、字体子集、数据迁移、双端一致性 |
| 审核风险 | 无 | 低—中：需按「工具 / 信息查询」类目提审，说明无在线支付 | 中—高：功能多、资金相关文案多 |
| 主要代价 | 无「我的小程序」常驻入口 | 多一层代理与跨境延迟；多一个端要维护 | 推翻 ADR 0001，长期维护两套后端 |

价格与配额依据：微信开放文档「计费说明」与腾讯云云开发购买方式文档，查证于 2026-11-06；
免费环境政策有活动截止日期（现行至 2026-12-31，可续期），落地前须复核。

## 合规要点（进入提审材料前必须固化）

1. 奖池 / 末尾三名罚金 / 支取 / 慈善捐赠是**线下资金记账**，系统不产生在线支付、不提供充值提现。
   提审说明与页面文案须明确这一点，避免被判金融 / 支付 / 资金池类目；个人主体也确实无法开通微信支付，
   二者恰好一致。
2. 名称与简介沿用中性品牌「**国战积分**」，不使用「三国杀」字样——第三方商标，且易触发游戏类目资质要求。
3. 类目走「工具 - 信息查询 / 记账」，避开社交、电商、金融。只读 MVP 更容易与类目对齐。
4. 房主密码按 `CONTEXT.md` 定义保持不变；若后续引入 openid 绑定玩家，须另开 ADR 修订词汇表与鉴权模型。

## 第二轮待决问题

1. 为 7 名玩家「少点一次链接」，是否值得备案周期 + 认证费 + 云开发月费 + 双端维护？
   群置顶 / 群公告 / 二维码 / 添加到主屏幕能否覆盖同一诉求？若可以，按最小复杂度原则结案为 A。
2. 若做，MVP 是否确认为「积分榜 + 奖池」两页只读，写操作全部留在 H5？
   这一条直接决定工程量与审核风险是否可控。
3. 是否接受云函数代理的跨境延迟，以及上线后约 19.9 元/月的持续费用？
4. 名称「国战积分」与「工具 - 信息查询」类目是否确认？

## 后果

- 选择 A：无工程改动，本 ADR 以「不新增端」结案，保留上述约束与成本对比供未来复用。
- 选择 B：须先完成小程序注册、认证与备案，再进入 SOP 第 2 步（方案蓝图）与第 3 步（按页代码）；
  云函数只做薄转发，业务逻辑仍留在 `worker/src/index.js`，避免平台锁定。
- 选择 C：须另开 ADR 废止或修订 ADR 0001，并处理 D1 数据迁移与 `worker/README.md` 部署说明。
- 本轮未产生新的领域术语，`CONTEXT.md` 不改动；若后续确定引入 openid / 订阅消息等概念，
  按 `docs/agents/domain.md` 的约定由 `/domain-modeling` 补词条。

### 前后端承载

**前端承载 = 微信客户端**。承载物是原生工程（wxml/wxss/js/json），由微信客户端渲染，
不是浏览器、不是 WebView 里的 H5。跨端框架（Taro / uni-app）只是编译到同一承载物，
多一层构建链；`web-view` 的承载物是 H5，个人主体不可用，已淘汰。

**后端承载 = 三选一，判别标准是「请求从哪发出」**：

| 承载 | 链路 | 需备案域名 | 本项目 |
| --- | --- | --- | --- |
| 云开发云函数（含云数据库） | `wx.cloud.callFunction` → 云函数 | 否 | ✅ 唯一零迁移入口 |
| **云函数代理现有 Worker** | 云函数 → `fetch` → Workers → D1 | 否 | ✅ **推荐** |
| 自建 API + 备案域名 | `wx.request` → 已备案域名 | 是 | ❌ 现有域名不合格 |
| 国内云托管 + 数据迁移 | 重写后端 | 视配置 | ⚠️ 推翻 ADR 0001 |

推荐链路：

```
前端（原生 2 页只读 MVP）
  └─ wx.cloud.callFunction
       └─ 云函数：薄转发 + 注入 X-House-Key + 超时/降级
            └─ 服务端 fetch（不受合法域名校验）
                 └─ 现有 Cloudflare Worker + D1
```

**职责边界（不可越界）**：

- 云函数只做转发与鉴权注入，**业务逻辑一律不搬**，`HOUSE_KEY` 放云函数环境变量、不进小程序包。
  这样避免平台锁定，也保证 `worker/src/index.js` 仍是唯一计算权威。
- 小程序端**不得复制** `calculateBottomThreeFines` / 积分公式 / 同分平摊逻辑。
  ADR 0004、0007 的并列边界规则很微妙，双端各算一份必然漂移；小程序只渲染 Worker 返回的派生结果。
- 字体：H5 的 171 个中文子集 woff2 不能照搬（撞主包 2MB），改用系统字体或按需 `wx.loadFontFace`。
- CORS 无需改动：现有 `Access-Control-Allow-Origin: *` 与允许 `X-House-Key` 头已兼容云函数服务端 fetch。
- 新增风险：国内云函数访问境外 Worker 有跨境延迟，须设超时与降级提示，不能假设链路稳定。

### 并行关系

备案与认证是**行政路径**，与代码正交：代码工程可立即开始，但正式版发布必须等备案完成。
因此若决定走 B，第一动作是提交小程序备案，而不是先写页面。

## 决策变更（2026-11-06 下午）

用户明确改为「**前后端都用微信小程序重写**」：前端原生小程序，后端微信云开发
（云函数 + 云数据库），不再复用 Cloudflare Worker / D1，也不再采用本 ADR 推荐的
B（云函数代理现有 Worker）。

**_Contradicts ADR 0014 的推荐链路_**：这实质是 C 的变体——不买域名备案、不迁国内服务器，
而是把后端整体搬进微信生态，从根上绕开合法域名约束。代价是后端重写与数据迁移，
收益是不再依赖任何境外链路。

影响：

- ADR 0001（Cloudflare D1 + Workers）在小程序端不再适用；若小程序上线成为主端，
  须另开 ADR 说明 H5 与小程序的数据关系（双写 / 迁移 / 只读归档），否则会出现两套账本。
- 领域规则不因换栈改变：积分公式、首亮与击杀加分、赛季三态、同分平摊、奖池与捐赠语义
  全部沿用 `CONTEXT.md` 与 ADR 0002–0013，已固化进 `docs/prompt-miniprogram-rewrite.md`。
- 仍绕不开：小程序自身工信部备案、个人主体类目限制、云开发上线后按套餐计费。
- 新增技术风险：D1 关系模型 → 云开发文档集合，必须显式保证赛季结算的原子性（数据库事务）
  与金额整数分（避免浮点误差）；两者已作为硬约束写进提示词。

本 ADR 状态仍为「需求确认中」：方案蓝图与代码生成待用户确认后按 SOP 第 2、3 步推进。
